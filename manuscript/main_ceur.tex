\begin{abstract}
    Traditional access control models, such as standard Role-Based Access Control (RBAC), often prove too rigid, rendering them inadequate for the dynamic, context-heavy threat landscapes characteristic of Internet of Things (IoT) environments. To address this limitation, we propose IoT-Access-Sentinel, a hybrid access control prototype that couples User Authorization Pre-checks with Large Language Model (LLM) reasoning to facilitate adaptive runtime decision-making. We evaluated the proposed system using a synthetic benchmark and a simulated replay harness integrated with the Wazuh Security Information and Event Management (SIEM) platform. Our findings indicate that while an isolated LLM reasoning layer remains highly vulnerable to adversarial prompt injection, coupling a Deterministic Validation Pre-filter with strict semantic delimiters significantly enhances the robustness of the system against the benchmark threat model. Ultimately, this proof-of-concept demonstrates that LLMs can successfully support context-aware authorization in IoT networks, provided that they are strictly constrained by a deterministic enforcement boundary and engineered with fail-secure defaults.
\end{abstract}

\section{Introduction}

The proliferation of Internet of Things (IoT) devices across critical infrastructure, smart environments, and industrial sectors has introduced profound security challenges for access-control systems. As devices transition from isolated components to interconnected ecosystems, authorization decisions must concurrently evaluate rigid identity policies and dynamic contextual factors, such as access time, device operational state, and the surrounding environment. Traditional approaches, such as standard Role-Based Access Control (RBAC), remain highly effective for deterministic enforcement; however, they frequently exhibit excessive rigidity when confronting semantic ambiguity in dynamic IoT environments. Although security-hardened API gateways can integrate temporal constraints, network rules, and basic signature checks to augment RBAC (herein referred to as the \textit{RBAC+Rules Baseline}), these configurations still lack the flexibility required to safely resolve contextually nuanced access scenarios. 

Furthermore, access control architectures within these networks must align with established security frameworks, such as MITRE ATT\&CK Mitigation M0801 (Access Management)~\cite{mitre2023attack}, which prioritizes User Identification and Verification. Adhering to M0801 demands auditable mechanisms to verify authorization boundaries, a requirement that becomes more complex when rules must dynamically adapt to contextual anomalies without sacrificing explainability.

Recent applications of generative artificial intelligence in IoT security have predominantly focused on offline policy generation and passive threat detection, leaving a critical gap in the active runtime access management. Bridging this gap remains difficult because conventional rule engines struggle to process natural language or context-heavy requests, whereas unconstrained Large Language Model (LLM) reasoning is notoriously vulnerable to prompt injection and adversarial manipulation. Consequently, systems that are sufficiently expressive to reason about ambiguous contexts are often too fragile to be placed directly in the critical path of authorization.

To address this gap, we introduce \textit{IoT-Access-Sentinel}, a hybrid framework that integrates the Deterministic Validation Pre-filter and multi-agent LLM reasoning within a unified runtime access-control pipeline. The system first executes the Deterministic Validation Pre-filter, which performs strict checks such as cryptographic token verification and user-device Access Control List (ACL) validation. Subsequently, only semantically ambiguous requests are routed to specialized LLM agents for context resolution. This architectural design preserves a deterministic enforcement boundary while selectively employing the LLM layer only when advanced semantic reasoning is required.

We evaluated our design using a custom synthetic benchmark and a simulated replay harness, processing Security Information and Event Management (SIEM) access alerts that represent both benign operational scenarios and targeted adversarial attacks. Our evaluation reveals that while an isolated LLM reasoning layer remains highly vulnerable to prompt injection under the benchmark threat model, coupling it with a Deterministic Validation Pre-filter and strict semantic delimiters substantially enhances the robustness of the decision.

This study makes the following contributions.

\begin{itemize}
    \item We propose a two-stage hybrid IoT authorization pipeline that tightly integrates deterministic pre-validation with multi-agent LLM reasoning to facilitate context-aware access decisions.
    \item We evaluate the proposed framework utilizing a synthetic benchmark comprising 102 benign/edge scenarios and 105 dedicated adversarial attacks, illustrating both the operational benefits and the inherent attack surface of LLM-assisted authorization under simulated conditions.
    \item We systematically analyze how deterministic sanitization, strict prompt delimiters, and fail-secure fallback mechanisms mitigate both structural and semantic attacks.
\end{itemize}

Section~\ref{sec:threat_model} defines the threat model and presents an adversarial evaluation. Section~\ref{sec:architecture} details the hybrid system architecture, and Sections~\ref{sec:evaluation} and beyond discuss the experimental methodology, performance results, systemic limitations and directions for future research.


\section{Related Work}\label{sec:related_work}

\subsection{LLM-based Access Control for IoT}

Recent studies have explored the integration of language models into IoT access control paradigms~\cite{llm4iot2024, edgegenai2024}, primarily focusing on synthesizing formal policies from natural language specifications.

For instance, LACE~\cite{lace2025} introduced a Language-based Access Control Engine that translates natural language policy descriptions into structured rules. By coupling LLM-based policy generation with formal verification via an Open Policy Agent (OPA), LACE achieves 88\% runtime decision accuracy. Although this illustrates a viable approach to LLM-assisted policy enforcement, its decision pathway introduces substantial runtime latency (2.66s per request), potentially precluding its deployment in time-sensitive IoT environments.

Similarly, CollabIoT~\cite{shastri2025llmdrivenautoconfigurationtransient} employs an LLM-driven capability-based access control scheme for transient IoT collaboration. This system focuses on proactive policy generation and device auto-configuration, reporting 100\% policy correctness and a low enforcement overhead. CollabIoT is best viewed as a complementary proactive approach focusing on token generation, whereas our work investigates reactive runtime authorization for semantically ambiguous requests.

Collectively, frameworks such as LACE and CollabIoT demonstrate the efficacy of LLMs in proactive policy creation and configuration. In contrast, our system explores reactive runtime authorization for semantically ambiguous requests. By restricting multi-agent reasoning to scenarios where deterministic validation fails, we optimize for the latency-critical nature of active IoT access management. \subsection{Traditional Access Control for IoT}

Traditional IoT access control relies predominantly on static, rule-based paradigms, such as Role-Based Access Control (RBAC)~\cite{rbac2004}, Attribute-Based Access Control (ABAC)~\cite{abac2012}, and capability-based models~\cite{capability2016}. Although these methods excel at deterministic validation, they systematically struggle to mitigate semantic threats and contextual anomalies~\cite{alaba2017internet, ouaddah2016fairaccess}.

To address these static limitations, DLBAC~\cite{dlbac2022} introduced a deep-learning-based access control method that utilizes neural networks to learn and predict access patterns. Although DLBAC improves static RBAC, it fundamentally lacks explainability. This opacity is problematic for verifying compliance with stringent security standards, such as the MITRE ATT\&CK Mitigation M0801 (Access Management). M0801 mandates mechanisms that not only verify user credentials and roles prior to granting access, but also maintain transparent logs for auditing. As black-box classifiers, deep learning models fail to provide the auditable explainability required by security operators during post-incident forensic investigations.

Similarly, RASA~\cite{rasa2021} proposed a risk-aware adaptive access control framework leveraging Bayesian networks. However, RASA's probabilistic risk scores lack semantic transparency, making it exceedingly difficult for security operators to ascertain \textit{why} a specific request was denied, which is a critical requirement for post-incident auditing and M0801 alignment. Our hybrid model explicitly addresses the auditability requirement by generating natural language reasoning reports to accompany each access decision.

Recent advances in multi-agent LLM architectures~\cite{multiagent2023} demonstrate that specialized agents frequently outperform monolithic general-purpose models on complex structured tasks. The IoT-Access-Sentinel adopts this paradigm by strictly separating context extraction from policy evaluation. This decoupled design aligns with contemporary risk management guidelines, including the NIST AI Risk Management Framework (AI RMF)~\cite{nist_airmf_2023} and builds upon established strategies for enforcing LLM security boundaries~\cite{doshi2024llms}.


\subsection{LLM Vulnerabilities in Cyber-Physical Systems}

Recent literature on Natural Language Access Control (NLAC)~\cite{lace2025, xu2022building} has heavily explored the translation of user intent into formal access policies. These systems typically relegate LLMs to policy \textit{generation} (intent $\rightarrow$ rules). Conversely, the IoT-Access-Sentinel leverages LLMs for active \textit{runtime evaluation} (rule + context $\rightarrow$ decision). This runtime delegation introduces severe risks that are well documented in prior Artificial Intelligence of Things (AIoT) and agentic security studies: prompt injection can actively manipulate model outputs, and adversarial techniques such as jailbreaking or payload splitting can successfully bypass standard alignment guardrails~\cite{yao2024survey, agentsec2025, wei2023jailbroken, liu2024autodan, fang2024llm}. These inherent vulnerabilities necessitate a deterministic containment boundary (Layer 0) in our architecture~\cite{doshi2024llms}.

\section{Threat Model and Adversarial Robustness}\label{sec:threat_model}

\subsection{Threat Model}

We operate under an adversarial threat model wherein malicious actors actively attempt to circumvent access controls via input manipulation, prompt injection, SQL injection, Unicode-based obfuscation, semantic evasion, and temporal and network-based bypasses. In our architecture, SQL injection payloads target the decision engine's local SQLite database—which stores session states, security policies, and decision audit logs—by attempting to manipulate dynamic query parameters during runtime policy lookups. We assume a well-resourced adversary capable of observing the system architecture, adapting their payloads iteratively, and directly interacting with the IoT network perimeter. We distinguish between two threat scenarios: (i) external attackers lacking valid credentials, and (ii) insider threats or compromised endpoints that possess valid credentials or target automated machine-to-machine services (such as sensors) that do not require user-level cryptographic authentication. While the former are deterministically blocked at Layer 0, the latter allow malicious payloads to reach Layer 1, thereby evaluating the semantic robustness of the LLM reasoning chain.

\subsection{Defense Mechanisms}

The proposed hybrid architecture implements a defense-in-depth strategy across two distinct layers. Layer 0 performs deterministic validation before any semantic reasoning. It applies schema validation to incoming alerts, executes security-critical authentication checks, and enforces pattern matching with known injection signatures. Crucially, Layer 0 defaults to a fail-secure DENY state whenever credentials are missing, malformed, or contextually invalid. 

Layer 1 subsequently processes only those requests that successfully traverse layer 0. This layer employs zero-trust prompting paradigms, enforces structured JavaScript Object Notation (JSON) output constraints, and leverages strict agent separation. This decoupled design significantly restricts prompt leakage and impedes attack propagation, allowing the Context and Policy agents to securely reason over subtle semantic attacks while generating auditable, natural-language explanations for their decisions.

To ensure a high-intensity stress test of the Layer 0 and Layer 1 defenses, this 105-scenario suite was evaluated separately from the main 204-run functional benchmark. The deterministic pre-filter successfully intercepted 66.7\% of the adversarial attempts (70/105) at Layer 0, preventing malicious payloads from reaching the downstream LLM agents. This interception rate is driven by two distinct validation mechanisms.
\begin{enumerate}
    \item \textbf{Format Validation Constraints}. Strict schema enforcement and character-set constraints on device identifiers (e.g., actively rejecting directional overrides or zero-width control characters) blocked 40 of the 70 cases. This included 10 Unicode right-to-left override (RTLO) attempts, 10 hidden character exploits, and 20 instances of malformed device type strings.
    \item \textbf{Regex-Based Pattern Matching}. Direct pattern matches against established attack signatures (e.g., SQL tautologies or explicit direct injection keywords) neutralized the remaining 30 cases, comprising 10 direct prompt injections, 10 role-play hijacks, and 10 payload splitting attempts.
\end{enumerate}

The remaining 33.3\% of the adversarial payloads (35/105) successfully bypassed Layer 0. These 35 scenarios targeted automated sensors which, under the global security policy, do not require user-level credentials. Consequently, they successfully traversed the Layer 0 authentication checks. These attacks predominantly rely on sophisticated semantic anomalies, such as contextual contradictions, chain-of-thought hijacking, and metadata smuggling, which appear structurally pristine and carry canonicalized text. However, these latent threats were successfully detected and neutralized by the contextual semantic comparison of the Policy Agent and zero-trust prompt constraints in Layer 1.

To mitigate the systemic risk of ceding absolute enforcement authority to a probabilistic model, Layer 0 functions as a containment boundary. Every ingested field is routed through a normalization pipeline utilizing the Unicode Normalization Form KC (NFKC) to neutralize homoglyph attacks. This is immediately followed by regex stripping of directional overrides (\texttt{\textbackslash u202A-\textbackslash u202E}), Bidi Isolates (\texttt{\textbackslash u2066-\textbackslash u2069}), and zero-width control characters. Unlike previous architectures (e.g., LACE), where formal OPA verification occurs \textit{after} LLM policy generation, our sentinel enforces these formal checks \textit{before} the LLM processes the data, ensuring that the language model reasons exclusively over sanitized, canonicalized contexts. 

Under our evaluation conditions, the LLM was completely bypassed for 42.2\% of the requests owing to the Layer 0 Fast-Path resolution (specifically, 86 out of 204 total functional evaluation runs were deterministically denied). For the remaining 57.8\% of ``semantically ambiguous'' requests (118 out of 204 runs), our multi-agent Layer 1 chain successfully resolved the complex context, achieving an overall system accuracy of 94.1\%, a statistically significant improvement over the 82.4\% accuracy observed in the baseline configuration.

\subsection{Observe: Wazuh SIEM Integration}

We integrated custom decoders and analytical rules within the Wazuh Manager~\cite{wazuh2024} to systematically parse IoT access logs and categorize events based on device typologies, including cameras, industrial sensors, and smart devices. The configured rule set actively monitors network violations, temporal anomalies, unauthorized device access attempts, and high-frequency behavioral deviations. Upon triggering a rule, these alerts are securely forwarded via a webhook to the FastAPI-based decision engine, carrying critical metadata, including the source IP, device type, user credentials, and precise timestamps.

\subsection{Decide: Hybrid Decision Pipeline}\label{sec:decision_pipeline}

The Decide stage operationalizes the two-layer defense-in-depth strategy. Layer 0 performs deterministic User Authorization Pre-checks before invoking any external LLM reasoning. It verifies token integrity and evaluates least-privilege mappings against preconfigured allowlists, immediately returning a fail-secure DENY decision when authentication or device membership checks fail~\cite{mitre2023attack}. Layer 1 exclusively processes requests that successfully satisfy the Layer 0 criteria. It provisions a specialized Context Agent to synthesize behavioral anomalies derived from the SIEM alert, alongside a Policy Agent tasked with evaluating this synthesis against the formalized security policy using strictly constrained prompt instructions. In our evaluation, this multi-agent pipeline is implemented using exactly two agents (the Context Agent and the Policy Agent) executed sequentially on a single instance of the 8B parameter Large Language Model (specifically, Llama 3.1 8B via Groq), with no consensus or auditor agents active during the runtime benchmark.

To mitigate the operational impact of remote LLM latency or transient service degradation, the pipeline incorporates a dual-mode fallback mechanism that reverts to a deterministic fail-secure behavior if Layer 1 exceeds its strictly defined timeout budget. Additionally, a semantic caching layer stores prior authorization decisions indexed by a SHA-256 hash of the device metadata, user role, and a minute-level temporal bucket. This cache employs a time-to-live (TTL) eviction policy (defaulting to 3600 s) to ensure periodic re-evaluation. Furthermore, any administrative modification to the global security policy triggers an immediate global invalidation of the cache, eliminating the risk of policy staleness during emergency security updates.

\subsection{Act: Distributed Enforcement via Wazuh Active Response}

The final authorization outcomes are translated into concrete enforcement actions via the Wazuh Active Response module. Upon generating a DENY decision, the policy engine dispatches a targeted firewall-drop command to the pertinent Wazuh agent via the REST API.

\begin{lstlisting}[language=json]
PUT /active-response
{
  "command": "firewall-drop",
  "agent_id": "<source_device_agent>",
  "arguments": ["-", "<source_ip>"]
}
\end{lstlisting}

This decentralized design facilitates distributed enforcement directly at the compromised source device, thereby avoiding a single point of failure and mitigating the limitations inherent to centralized gateway blocking. The network blocking duration remains fully configurable and defaults to 3600 s.

\section{Evaluation Methodology}\label{sec:evaluation}

\subsection{Evaluation Datasets and Scenarios}

We systematically evaluated the IoT-Access-Sentinel by leveraging three distinct analytical datasets: (1) a comprehensive functional benchmark comprising 102 test scenarios, (2) a dedicated, high-intensity red-team adversarial suite consisting of 105 diversity-driven attack attempts, and (3) a high-concurrency stress test dataset comprising 137 simulated requests used to evaluate system availability and latency distribution under load. The 102 functional benchmark scenarios span critical security enforcement categories: User Authorization, Basic Evasion (evaluating rudimentary regex-based SQL/XSS/prompt injection filters), Temporal and Network Policies, Device-Specific Rules, and complex Edge Cases.

To preclude class imbalance and ensure analytical rigor, 102 functional scenarios were distributed across 45 ALLOW and 57 DENY configurations. Each scenario was executed twice (yielding 204 total runs) to evaluate both the uncached and cached pathways of the agent. Conversely, the separate 105 red-team adversarial scenarios strictly represent 100\% DENY states, as they exclusively focus on advanced evasion prevention and adversarial robustness under severe attack configurations.

Ground-truth expectations were manually derived and validated against established security policies. Each scenario deterministically specifies the device metadata, user credentials, event timestamp, and requisite ground-truth authorization decision (ALLOW/DENY).

\subsubsection{Noise-Augmented Scenarios}
To partially mitigate the inherent limitations of purely synthetic datasets, we incorporated a supplementary suite of 10 noise-augmented scenarios, which were deliberately designed to emulate the pervasive data-quality degradation frequently observed in production Wazuh deployments. These scenarios test the pipeline's resilience against (i)truncated or malformed timestamps resulting from misconfigured syslog forwarding, (ii)unrecognized JSON fields introduced by Wazuh schema drift across version upgrades, (iii)mixed-case and whitespace-padded device identifiers characteristic of heterogeneous device inventories, (iv)high-entropy rule descriptions injecting terminal escape sequences, hex codes, CVE references, MITRE ATT\&CK technique IDs, and threat intelligence metadata, (v)empty or null authentication fields stemming from expired session cookies, (vi)Unicode-accented device nomenclature from internationalized environments, and (vii)non-standard protocol versioning strings. Although these augmented scenarios cannot entirely replace validation against live network captures, they provide a structured stress test of the parsing and normalization boundary under conditions that approximate realistic production alert noise.

\subsubsection{Stress Testing and Availability Dataset}\label{sec:stress_test_dataset}
To evaluate the system's availability, throughput, and fail-secure behavior under operational load, we constructed a third dataset consisting of a high-concurrency replay of 137 access requests. This stress test harness simulates a peak-traffic event where 5 concurrent tasks replay camera access requests (using credentials from a security administrator, Alice, requesting access to camera-office-01). To evaluate the decision engine's resilience to API latency and timeout spikes, we modeled remote LLM API latency using two distinct probability distributions: a standard Normal distribution ($N(\mu=115\text{ ms}, \sigma=45\text{ ms})$) and a heavy-tailed Log-Normal distribution ($LogN(\mu_{\ln}=\ln(115)\approx4.745, \sigma_{\ln}=0.45$)), reflecting the tail latencies observed in cloud-based LLM APIs. The system's timeout budget was constrained to a strict 150~ms limit, forcing the pipeline to fall back to a fail-secure DENY decision when the latency budget is exceeded, thereby enabling a controlled evaluation of system safety under stress.

\subsection{Baseline Comparison}

To quantitatively isolate the performance gains strictly attributable to our multi-agent LLM architecture, we implemented a production-representative \textit{RBAC+Rules Baseline}. To ensure a fair ablation, this baseline executes the exact same deterministic codebase as Layer 0 of our proposed hybrid system, entirely omitting Layer 1 (the LLM reasoning chain). It applies four deterministic validation mechanisms: (1)~session token verification for user authentication; (2)~strict Access Control Lists (ACLs) bounding users to authorized device identifiers; (3)~standard CIDR-based subnet validation coupled with scheduled temporal filtering; and (4)~regex-based pattern matching on incoming text fields to intercept elementary SQL injection, Cross-Site Scripting, and direct prompt injection substrings.

By mirroring a security-hardened API gateway, this baseline exceeds the defensive capabilities of a rudimentary RBAC model that only evaluates user roles. Using this shared-code configuration as the comparative anchor ensures that any observed accuracy improvements in the hybrid system stem entirely from its advanced contextual reasoning, rather than implementation disparities.


\subsection{Evaluation Metrics and Statistical Testing}

To ensure the statistical validity of our findings, we used McNemar's test of significance for paired binary classification outcomes ($\alpha=0.01$), generated 95\% confidence intervals for overall accuracy and error rates, and applied category-wise accuracy stratification to precisely identify the specific scenarios where LLM reasoning provides an operational advantage.

Furthermore, the operational viability of the system was evaluated based on end-to-end latency (from alert receipt to enforcement command generation), throughput (measured in concurrent requests per second), and overall resource footprint (memory and CPU utilization).

\subsection{Overall Performance Comparison}

The 204 runs were generated by executing the 102 test scenarios twice: once to evaluate the end-to-end decision logic from a cold start (uncached path) and once to verify that the local semantic caching layer consistently stores and returns the identical authorization decision upon subsequent queries (cached path). Because these cached runs are deterministic duplicates of the uncached runs, they do not constitute independent samples and are excluded from all statistical significance calculations. All reported McNemar's test statistics and confidence intervals are computed strictly on the 102 unique, independent test scenarios to satisfy the paired independence assumption.

Crucially, the RBAC+Rules Baseline implements identical deterministic authentication, role mapping, temporal constraints, and subnet filtering as Layer 0 of our proposed hybrid system. Therefore, the 11.7\% accuracy improvement achieved by the hybrid system (94.1\%) over the RBAC+Rules Baseline cleanly isolates the semantic gain provided by the multi-agent LLM reasoning layer (Layer 1) when resolving complex requests for which structural rules alone lack the expressivity to accurately authorize.

McNemar's test, computed on the 102 independent scenarios ($\chi^2 = 7.56$, $p < 0.01$), confirms that this accuracy improvement is statistically significant at the $\alpha = 0.01$ level, allowing us to confidently reject the null hypothesis of equivalent performance. The non-overlapping confidence intervals further substantiate this conclusion.

We explicitly reconcile the relationship between this functional accuracy benchmark and the real-time latency/timeout model. The 94.1\% accuracy reported in Table~\ref{tab:overall} represents the logical and semantic correctness of the hybrid pipeline under normal, infinite-budget latency conditions (where the LLM is permitted to complete its reasoning). If the strict 150~ms timeout budget were applied directly to the uncached cold-start path, the effective operational accuracy would degrade. Specifically, because camera (full-LLM) scenarios exhibit an average latency of 156~ms (as shown in Table~\ref{tab:performance}), a significant portion of legitimate, uncached camera requests would time out and default to a fail-secure DENY decision. This would convert should-ALLOW requests into operational False Denies, thereby reducing the system's operational recall during the cold start. However, the local semantic caching layer (with a latency of $<$1~ms) mitigates this trade-off: once the cache is populated by a cold-start request, all subsequent requests are resolved instantaneously below the 150~ms limit, avoiding any latency-induced timeouts. Thus, the system deliberately prioritizes network security (via fail-secure DENY) and availability (via caching) over continuous real-time capability during initial cache misses.

The deterministic-only baseline achieved an accuracy of 82.4\% using standard access control primitives. While highly effective for structured validation, it lacks the semantic depth required to mitigate complex evasion tactics and nuanced edge case authorization scenarios.

The introduction of a single-agent LLM marginally improved the accuracy to 86.3\%, indicating that language-based reasoning provides utility in resolving ambiguity, where deterministic rules prove overly rigid. However, the fully hybrid configuration substantially outperformed both alternatives. It is important to emphasize that this peak performance (94.1\%) cannot be attributed to a single component; rather, it reflects the synergistic effect of decoupling the context from the policy (multi-agent reasoning), pre-sanitization, and deterministic User Authorization Pre-checks.

This ablation also quantifies a critical cost--accuracy trade-off. The Hybrid system operates with a \textit{Layer 0 Fast-Path Rate} of 42.2\%, meaning that 86 out of the 204 requests failed the initial deterministic checks and were immediately denied without incurring the computational latency of an LLM invocation. This fast path mechanism dramatically reduces the operational overhead while anchoring the system to deterministic security principles. Only genuinely ambiguous requests, such as those where user authorization succeeds but temporal or network context presents a conflict, are escalated to the multi-agent reasoning chain.

\subsection{Confidence Derivation and Calibration Analysis}

Unlike traditional classification models that rely on logit-based probabilities, the IoT-Access-Sentinel logs Verbalized Semantic Confidence exclusively for auditing purposes. During Layer 1 policy evaluation, the LLM agent is instructed to append a numerical confidence score ($c \in [0, 1]$) along with its generated reasoning. This score represents the agent's semantic certainty regarding the policy context. While intentionally excluded from live decision gating, these scores were retained for post-hoc calibration analyses.

To quantify the calibration quality, we calculated the Expected Calibration Error (ECE) across the 204 evaluation decisions using 10 equal-width bins:
\[
\text{ECE} = \sum_{b=1}^{B} \frac{n_b}{N} \left| \text{acc}_b - \text{conf}_b \right|
\]
where $B=10$ bins, $n_b$ represents the number of samples in bin $b$, $N=204$ is the total sample count, $\text{acc}_b$ denotes the empirical accuracy of bin $b$, and $\text{conf}_b$ is the mean verbalized confidence in bin $b$.

While the raw ECE of 0.0554 might superficially suggest moderate calibration, deeper inspection reveals a clear calibration failure; specifically, all 204 confidence scores clustered tightly within the highest bin $[0.95, 1.0]$ (mean $= 0.997$). Crucially, the 12 incorrect decisions were all assigned a maximum confidence of $1.0$. This extreme concentration demonstrates the systematic overconfidence inherent in LLM-generated verbalized probabilities: the model expresses absolute certainty independent of its actual empirical correctness. While the raw ECE appears mathematically acceptable, the model's inability to discriminate between correct and incorrect decisions confirms that verbalized confidence is currently non-actionable for runtime gating and must be treated strictly as an ordinal audit artifact. To render these scores viable for automated runtime gating, formal temperature-scaling calibration or ensemble-based variance estimation is required.

\subsection{Mitigation Performance: Semantic Caching}\label{sec:caching_results}
The Semantic Caching Layer (detailed in Section~\ref{sec:decision_pipeline}) serves as the primary mitigation against the availability risks inherent to remote LLM reliance. By bypassing inference for repeated access requests, it reliably delivers sub-millisecond responses and ensures the continuous enforcement of cached decisions during transient cloud API outages.

When API timeouts or internal pipeline failures occur, the hybrid system defaults to DENY. Although these fail-secure actions (35 instances out of 137 initiated requests under the log-normal model) temporarily degrade system availability, they categorically eliminate the risk of unauthorized network access during periods of system instability. These 35 fail-secure denials are counted as operational False Denies in our load-testing report, directly illustrating how latency-induced timeouts degrade the recall metric in practice. We emphasize that while the 102 functional scenarios (204 runs) were evaluated under normal conditions without the 150~ms timeout to isolate the model's logical decision accuracy, enforcing the 150~ms limit under load trades off operational availability (via fail-secure denials of legitimate requests) to guarantee security. In critical infrastructure security, this demonstrates that reduced availability does not equate to a degraded access control, as the hybrid system still correctly blocks all unauthorized access attempts.

Furthermore, a counterfactual ablation within the dedicated red-team evaluation (Section~\ref{sec:adversarial_eval}) demonstrates the vulnerability of an unconstrained LLM configuration. As shown in the ``LLM Only'' column of Table~\ref{tab:adversarial}, the LLM operating without Layer~0 input sanitization or structured prompt delimiters detected only 41.0\% of the 105 adversarial payloads, suffering from a 0\% detection rate on sophisticated prompt injections, role-play hijacks, contextual contradictions, and metadata smuggling. Upon implementing structural mitigations (Layer~0 sanitization and strict semantic delimiters), the hybrid system successfully neutralized all the evaluated evasion attempts (100\% detection rate). This stark contrast underscores the necessity of a defense-in-depth approach, demonstrating that LLM reliability in adversarial conditions is fundamentally dependent on deterministic data bounding.

\section{Discussion}

\subsection{Agent Security and Authorization Boundaries}

To address the trust--authorization gap inherent in probabilistic agentic systems~\cite{nistai2024}, we established explicit authorization boundaries and strictly scoped tool-use privileges for the sentinel architecture.

The multiagent framework operationalizes a ``need-to-know'' data partitioning strategy. The \textit{Context Agent} ingests raw network and device metadata to synthesize a situational report, whereas the \textit{Policy Agent} receives this synthesis along with the formalized security policies. This deliberate separation dramatically reduces the attack surface, mitigating the risk that a compromised agent could autonomously fabricate contextual factors to justify an unauthorized bypass.

Crucially, unlike general-purpose autonomous agents, the sentinel does not expose open-ended tool execution. The LLM agents operate exclusively within a ``read-only'' reasoning sandbox, constrained to generating a structured \texttt{EnforcementAction} (DENY, PERMIT, or ESCALATE). The actual execution against the security infrastructure (e.g., dispatching a Wazuh active response to drop an IP) is orchestrated by a deterministic, non-LLM \textit{Enforcement Controller}. This architectural decoupling isolates the enforcement mechanisms from prompt injection vulnerabilities in the reasoning layer of the LLM.

Furthermore, the sentinel strictly restricts the LLM's authority to the semantic resolution of existing policy conflicts. The agentic layer fundamentally cannot author new security policies or modify the Layer 0 blocklists. Any LLM reasoning failure, timeout, or internal processing error triggers a fail-secure DENY status.

\subsection{Systemic Availability and Operational Risks}

The delegation of runtime authorization to LLM reasoning introduces a critical trade-off between security and availability. While our fail-secure architecture ensures that any timeout or processing error results in a DENY decision, this design creates an asymmetric resource consumption vector. Sophisticated adversaries can bypass Layer 0 deterministic checks with syntactically pristine requests, forcing resource-intensive LLM invocations that deplete API quotas and trigger timeout-driven denials for legitimate users. Our empirical DoS analysis confirms this vulnerability: at an attack intensity of 500 requests, the legitimate user denial rate surged from a baseline of 24\% to 38\%, demonstrating that the fail-secure mechanism can be leveraged as a denial-of-service amplification vector.

To mitigate this risk, we implemented a per-IP sliding window rate limiter that denies requests instantaneously once a source IP exceeds a defined threshold (e.g., 10 requests per 60 s). While this effectively contains single-source attacks, production-grade deployments must transition toward localized Small Language Models (SLMs) and adaptive rate limiting based on request complexity to resist distributed botnet attacks.

Beyond availability, the system incorporates essential integrity and privacy guardrails. Every agent decision is immutably logged as a ``Policy Explanation'' within the SIEM, enabling forensic auditing of potential hallucinations. Furthermore, to address the privacy risks associated with transmitting IoT metadata to third-party cloud APIs, the sentinel employs strict PII redaction at Layer 0. Future iterations will prioritize the adoption of Local Differential Privacy (LDP) and on-premise inference to eliminate the data exposure surface entirely.

\subsection{Deployment Considerations}

The Wazuh agent maintains a modest resource footprint ($\sim$35 MB RAM), suggesting feasibility for deployment on higher-tier IoT endpoints such as smart cameras and industrial gateways. However, ultra-constrained microcontrollers (e.g., ESP8266) cannot support direct agent installation and require a reverse proxy gateway. A successful production rollout requires secured manager connections and verifiable fail-safe testing under induced network partition scenarios. For highly constrained environments, routing traffic through a centralized proxy gateway remains the most practical choice to consolidate policy enforcement while eliminating per-device overhead.

\subsection{Limitations and External Validity}

A primary limitation is the reliance on synthetic Wazuh alerts rather than live edge network traffic, which contains higher noise ratios and protocol drift. While noise-augmented scenarios stress-test the parsing boundaries, they do not fully replicate production complexities. Additionally, the use of a cloud-based LLM (Llama 3.1 via Groq) introduces tail-latency risks, potential DoS amplification, and privacy concerns regarding the transmission of IoT metadata to third-party APIs. Finally, as the evaluation was conducted within a simulated harness rather than on physical hardware, conclusions regarding thermal and hardware feasibility remain theoretical.

\subsection{Future Work}

Future research should prioritize empirical validation using real-world network traces from live IoT deployments and physical edge testbeds. To comprehensively address latency, privacy, and DoS vulnerabilities, subsequent architectures should transition from cloud-dependent APIs to compact, localized Small Language Models (SLMs) explicitly fine-tuned for IoT threat typologies. Furthermore, integrating active LLM reasoning with formal token-based models (e.g., Semantic Leases) and applying formal calibration methodologies, such as temperature scaling or conformal prediction, will be essential to transform overconfident LLM verbalizations into probabilistically sound, actionable signals for adaptive runtime decision gating.

\section{Conclusion}

We present IoT-Access-Sentinel, a hybrid multi-agent framework designed to secure IoT access control by integrating deterministic User Authorization Pre-checks with Large Language Model (LLM) contextual reasoning. Our empirical evaluation on a synthetic benchmark demonstrated that while isolated LLM reasoning layers are highly susceptible to adversarial prompt injection, wrapping them in a deterministic containment boundary and strict semantic delimiters successfully neutralized 100\% of the evaluated evasion attempts against the evaluated synthetic threat model while achieving a 94.1\% overall decision accuracy.

By directly integrating with an established SIEM ecosystem (Wazuh), the Sentinel framework provides a practical, fail-secure template for safely deploying probabilistic LLMs in critical authorization pathways. Although future validation against live network traffic and physical edge hardware is required to confirm production readiness, this study establishes a clear imperative: future agentic security architectures cannot rely on generative capabilities alone but must firmly anchor semantic flexibility within deterministic boundaries.
