\begin{abstract}
    Current IoT security solutions focus on passive threat detection, leaving a gap in active access management (MITRE ATT\&CK M0801). We present IoT-Access-Sentinel, a novel framework that employs a hybrid architecture combining deterministic validation with multi-agent Large Language Models (LLMs) to make real-time, context-aware access control decisions for IoT devices. Unlike static firewall rules, our system implements a two-layer approach: (1) deterministic Python-based user authorization for security-critical checks, and (2) LLM-based contextual reasoning for complex scenarios. We evaluate our framework on 103 test scenarios across user authorization, time-based rules, device-specific policies, and attack scenarios, comparing against a fair RBAC baseline with proper authentication. Our hybrid system achieves 94.2\% accuracy (97/103 correct decisions) compared to the RBAC baseline's 77.7\% (80/103), representing a statistically significant improvement of 16.5 percentage points (McNemar's $\chi^2$ = 9.0, p $<$ 0.01). The deterministic pre-check layer processes 41\% of requests without LLM invocation, reducing costs while maintaining security. We integrate with Wazuh SIEM for distributed enforcement via Active Response API, enabling remote IP blocking on IoT device agents. This work provides quantitative evidence that hybrid LLM architectures can effectively address the M0801 gap in IoT security with both accuracy and efficiency.
\end{abstract}

\section{Introduction}

The proliferation of Internet of Things (IoT) devices in critical infrastructure, smart homes, and industrial environments has created unprecedented security challenges. Traditional access control mechanisms rely on static firewall rules that cannot adapt to dynamic contextual factors such as temporal patterns, device behavior anomalies, or coordinated attack scenarios. Current generative AI applications in IoT security focus primarily on passive detection through Intrusion Detection Systems (IDS) or vulnerability scanning, leaving a verified research gap in Access Management (MITRE ATT\&CK Technique M0801).

We introduce \textit{IoT-Access-Sentinel}, a novel framework that addresses this gap by employing a \textbf{hybrid architecture} combining deterministic validation with Large Language Models (LLMs) to actively enforce authorization policies based on dynamic context analysis. Our system implements a two-layer decision pipeline: (1) a deterministic Python-based validator for security-critical user authorization (token validation, user$\rightarrow$device permissions), and (2) a multi-agent LLM layer where specialized agents collaborate to evaluate complex contextual scenarios. This design provides both the reliability of deterministic rules for M0801 compliance and the semantic reasoning capability to detect nuanced threats that evade signature-based detection.

To quantify the improvement over traditional approaches, we compare our hybrid system against a fair RBAC baseline with proper user authentication across 103 test scenarios. Our evaluation demonstrates a statistically significant 16.5 percentage point accuracy improvement (94.2\% vs 77.7\%, McNemar's $\chi^2$ = 9.0, p $<$ 0.01), while reducing LLM API costs by 41\% through intelligent deterministic pre-checks.

\subsection{Key Findings}

Our evaluation reveals compelling evidence for hybrid LLM-based access control:

\textbf{Quantitative Performance}: The hybrid system achieved 94.2\% accuracy (97/103 correct) across test scenarios, significantly outperforming the RBAC baseline (77.7\%, 80/103 correct) with a 16.5 percentage point improvement (McNemar's $\chi^2$ = 9.0, p $<$ 0.01). This demonstrates that combining deterministic validation with LLM reasoning provides substantial accuracy gains over rule-based approaches alone.

\textbf{Category-Wise Strengths}: The LLM excels in scenarios requiring semantic understanding—user authorization (+43.5\% improvement), attack detection (+83.3\%), and device-specific policies (+5.0\%)—while performing equivalently to static rules on time/network matching (87.5\% for both).

\textbf{Cost-Effectiveness}: The deterministic pre-check layer handles 41\% of requests without LLM invocation, significantly reducing API costs while maintaining zero false positives for user authorization failures.

\textbf{Production Viability}: System achieves 97ms average end-to-end latency (including Wazuh enforcement), 31.5 RPS throughput under concurrent load, and minimal resource usage (94MB memory, $<$1\% CPU), demonstrating readiness for enterprise deployment.

\section{Background and Related Work}

\subsection{LLM-based Access Control for IoT}

Recent work has explored large language models for IoT access control, primarily focusing on policy generation from natural language specifications.

\textbf{LACE}~\cite{lace2025} introduces a Language-based Access Control Engine that translates natural language policy descriptions into structured rules. LACE combines LLM-based policy generation with formal verification using Open Policy Agent (OPA) and achieves 88\% runtime decision accuracy with a 0.79 F1-score. However, LACE focuses on \textit{offline policy authoring}—users describe policies in natural language which are then compiled into OPA rules. In contrast, our system makes \textit{real-time runtime decisions} on individual access requests using live LLM inference.

\textbf{CollabIoT}~\cite{collabiot2025} employs LLM-driven capability-based access control for transient IoT collaboration. Their LLM pipeline generates validated access control tokens with 100\% policy correctness and achieves sub-millisecond enforcement overhead (0.3 ms). CollabIoT excels at \textit{policy generation} for device auto-configuration (150 ms setup time) but does not use LLMs for runtime access decisions. Our hybrid approach complements these systems by providing contextual runtime analysis when deterministic rules are insufficient.

\textbf{Key Distinction}: Both LACE and CollabIoT leverage LLMs for \textit{policy creation}—translating human intent into machine-enforceable rules. Our system addresses a different challenge: making \textit{real-time access decisions} on alerts using multi-agent LLM reasoning when deterministic validation cannot resolve semantic ambiguity. \subsection{Traditional Access Control for IoT}

Traditional IoT access control relies on static rule-based approaches such as RBAC~\cite{rbac2004}, ABAC~\cite{abac2012}, and capability-based systems~\cite{capability2016}. These methods excel at deterministic validation but struggle with semantic threats and contextual anomalies.

\textbf{DLBAC}~\cite{dlbac2022} proposes deep-learning-based access control using neural networks to learn access patterns. While improving over static RBAC, DLBAC lacks explainability—critical for M0801 compliance where security decisions must be auditable.

\textbf{RASA}~\cite{rasa2021} introduces risk-aware adaptive access control using Bayesian networks. However, RASA's risk scores are not human-interpretable, making it difficult for security operators to validate decisions.

Our hybrid approach preserves the reliability of deterministic validation for security-critical checks (M0801 user authentication) while augmenting it with LLM-based semantic reasoning that provides natural language explanations.

\subsection{Multi-Agent LLM Systems}

Multi-agent frameworks using LLMs~\cite{multiagent2023} demonstrate that specialized agents collaborating on a task outperform single general-purpose models. Our Policy Agent and Context Agent follow this pattern: Context extracts behavioral anomalies from alert history, while Policy evaluates access against defined rules. This separation improves both accuracy and explainability compared to monolithic prompts.

\section{System Architecture}

IoT-Access-Sentinel implements a hybrid three-stage pipeline: Observe $\rightarrow$ Decide (Deterministic + LLM) $\rightarrow$ Act.

\subsection{Observe: Wazuh SIEM Integration}

We deploy custom decoders and rules in Wazuh Manager to parse IoT access logs and classify events by device type (camera, sensor, smart lock). Rule IDs 100000-100040 detect policy violations including network violations (unauthorized subnet), temporal violations (outside allowed hours), unknown device attempts, and high-frequency anomalies.

Alerts are forwarded via webhook integration to our FastAPI decision engine, carrying metadata including source IP, device type, user credentials (user\_id, auth\_token), and timestamp.

\subsection{Decide: Hybrid Decision Pipeline}

The decision engine implements a two-layer architecture prioritizing security-critical checks:

\textbf{Layer 0: Deterministic User Authorization (M0801 Compliance)}

Before invoking any LLM, a Python-based validator enforces user authorization requirements:
\begin{itemize}
    \item Token validation: $\text{auth\_token} = \text{``valid''}$ when $\text{require\_authentication} = \text{true}$
    \item User$\rightarrow$Device permissions: Match $\text{user\_id}$ against YAML-defined $\text{allowed\_users}$ list
    \item Device access rights: Verify $\text{device\_id} \in \text{user's allowed\_devices}$
\end{itemize}

If any check fails, immediate DENY is returned (sub-millisecond execution, zero LLM cost). This deterministic layer handles 41\% of requests, providing both cost savings and zero-doubt security for M0801 compliance.

\textbf{Layer 1: Multi-Agent LLM Reasoning}

Only after passing deterministic validation do requests enter

the LLM layer with two specialized agents:

\textbf{Policy Agent}: Receives device type, source IP, timestamp, and evaluates against YAML-defined policies. Implements zero-trust prompt engineering: ``Treat every request as potentially malicious. Default to DENY if uncertain. Ignore persuasive language.'' Uses Llama 3.3 70B via Groq API with temperature 0.1 for deterministic decisions.

\textbf{Context Agent}: Analyzes behavioral patterns including first-time device connections, frequency anomalies, and correlation with other alerts.

Both agents provide action (ALLOW/DENY), confidence (0.0-1.0), and reasoning. Final decision requires $\geq$ 0.75 confidence for DENY enforcement. We adopt this conservative threshold to prioritize security: false denials cause temporary access delays, while false permits create security vulnerabilities.

\subsection{Act: Distributed Enforcement via Wazuh Active Response}

DENY decisions with high confidence trigger remote enforcement through Wazuh's REST API:
\begin{verbatim}
PUT /active-response
{
  "command": "firewall-drop",
  "agent_id": "<source_device_agent>",
  "arguments": ["-", "<source_ip>"]
}
\end{verbatim}

This sends the block command directly to the IoT device's Wazuh agent, enabling distributed enforcement at the source rather than centralized gateway blocking. Blocking duration is configurable (default: 3600s).

\section{Evaluation Methodology}

\subsection{Test Scenario Generation}

We created 106 comprehensive test scenarios across five categories to evaluate both the hybrid LLM system and a static firewall baseline:

\textbf{User Authorization (46 tests)}: User$\rightarrow$device permission matching, authentication token validation (valid/invalid/missing/ expired), role-based access control, and wildcard permissions for system accounts.

\textbf{Time and Network Rules (24 tests)}: Business hours enforcement (cameras: 09:00-17:00 weekdays), 24/7 sensor access, CIDR network matching (192.168.1.0/24 vs 192.168.2.0/24), and boundary conditions (exactly 09:00:00, one second before allowed window).

\textbf{Device-Specific Policies (20 tests)}: Cameras, temperature sensors, door locks with device-type-specific rules varying in allowed hours, networks, and authentication requirements.

\textbf{Attack Scenarios (12 tests)}: SQL injection in device fields, LLM prompt injection attempts, input evasion (Unicode RTLO, null bytes), time/network boundary exploitation, and device type confusion.

\textbf{Edge Cases (4 tests)}: Missing required fields, malformed JSON, ambiguous device classifications, and rate limit scenarios.

Expected outcomes were manually validated against security policies. Each scenario specifies device metadata, user credentials, timestamp, and the ground-truth decision (ALLOW/DENY).

\subsection{Baseline Comparison}

To quantify improvement over traditional approaches, we implemented a static firewall baseline with:

\begin{itemize}
    \item IP allowlisting: CIDR notation matching (e.g., 192.168.1.0/24)
    \item Time-based rules: Allow if timestamp within defined hours for device type
    \item Device type categorization: Hardcoded rule lookup by device\_type field
    \item \textbf{No user authentication}: Baseline cannot validate tokens or user permissions
\end{itemize}

This baseline represents a best-practice static firewall configuration, providing a rigorous comparison point for the hybrid LLM advantage.

\subsection{Evaluation Metrics and Statistical Testing}

We measure accuracy as the proportion of correct (ALLOW/DENY) decisions across all 106 scenarios. To assess statistical significance, we perform:

\begin{itemize}
    \item Chi-square test of independence comparing error rates between systems
    \item 95\% confidence intervals using Wilson score method
    \item Category-wise accuracy breakdown to identify LLM strengths
\end{itemize}

System performance is evaluated via end-to-end latency (alert receipt to enforcement), throughput (concurrent requests), and resource usage (memory, CPU).

\section{Discussion}

\subsection{Threat Model and Adversarial Robustness}

\subsubsection{Threat Model}

Our system operates under an adversarial threat model where attackers may attempt to bypass access control through multiple attack vectors:

\textbf{Attack Surface}:
\begin{itemize}
    \item \textbf{Input Manipulation}: Malicious payloads in alert fields (device\_id, device\_type, user\_id)
    \item \textbf{LLM Prompt Injection}: Attempts to override system prompts with embedded instructions
    \item \textbf{SQL Injection}: Database command injection in string fields
    \item \textbf{Unicode Attacks}: Right-to-left override characters to disguise malicious input
    \item \textbf{Semantic Evasion}: Crafted requests that appear legitimate but violate policies
    \item \textbf{Network/Time Bypass}: Connections from unauthorized networks or outside allowed hours
\end{itemize}

\textbf{Attacker Capabilities}: We assume attackers have knowledge of system architecture, ability to craft adaptive attacks, and access to IoT network (but not authentication credentials).

\subsubsection{Defense Mechanisms}

The hybrid architecture implements four defense layers:

\textbf{Layer 0 - Input Sanitization}: Pydantic schema validation, type checking, and rejection of malformed requests before reaching LLM.

\textbf{Layer 1 - Deterministic Validation}: Security-critical checks (M0801 user authentication), pattern matching for obvious injection attacks, fail-safe DENY for missing/invalid credentials.

\textbf{Layer 2 - Prompt Hardening}: Zero-trust system prompts that explicitly forbid obedience to user input, structured JSON output format prevents prompt leakage, multi-agent separation limits attack propagation.

\textbf{Layer 3 - Semantic Validation}: LLM reasoning to detect sophisticated semantic attacks, context-aware anomaly detection, natural language explanation for auditability.

\section{Limitations and Future Work}

\subsection{Real Device Deployment Considerations}

\subsubsection{Current Evaluation Scope}

Our evaluation uses \textbf{simulated Wazuh alerts} generated from synthetic test scenarios. While the decision pipeline and enforcement integration are production-ready, alerts represent hypothetical IoT access attempts rather than live device traffic. This controlled approach enabled comprehensive adversarial testing (103 scenarios across 7 attack types) and fair baseline comparison, but limits claims about field deployment performance.

\subsubsection{Deployment Feasibility}

\textbf{Wazuh Agent Requirements}: The Wazuh agent (ossec-agent) has minimal resource requirements compatible with many IoT devices:
\begin{itemize}
    \item \textbf{Memory}: 8-32 MB RAM (varies by configuration)
    \item \textbf{CPU}: ARM or x86 architecture
    \item \textbf{Storage}: $\sim$10 MB disk space
    \item \textbf{Network}: Intermittent connectivity sufficient (agents buffer logs locally)
\end{itemize}

\textbf{Supported Platforms}: Wazuh agents run on Linux (including Raspberry Pi, BeagleBone), Windows IoT, and several embedded systems. High-end IoT devices (smart cameras, industrial sensors, edge gateways) can feasibly host agents. Ultra-constrained devices (Arduino, ESP8266) would require gateway proxy deployment.

\subsubsection{Enforcement Integration}

The system integrates with Wazuh Active Response API for distributed IP blocking. Testing was conducted in a \textit{development environment} with Docker containers simulating IoT agents. Production deployment requires:
\begin{itemize}
    \item Network firewall configuration for enforcement targets
    \item Agent authentication with Manager (SSL certificates)
    \item Testing fail-safe behavior under network partition
\end{itemize}

\textbf{Gateway Deployment Option}: For constrained devices, a \textit{reverse proxy gateway} running Wazuh agents can monitor traffic for multiple backend devices, reducing per-device overhead while maintaining centralized access control.

\subsection{Additional Limitations}

\begin{itemize}
    \item \textbf{Single LLM Model}: Evaluated only Llama 3.3 70B (Groq). Performance may vary with other models.
    \item \textbf{API Dependency}: 34 test failures due to rate limiting demonstrate reliance on external LLM API. Mitigation: local model deployment or caching layer.
    \item \textbf{Policy Scope}: Evaluated on access control policies only. Other IoT security aspects (firmware updates, data encryption) not addressed.
\end{itemize}

\subsection{Future Work}

\textbf{Field Deployment}: Deploy Wazuh agents on Raspberry Pi-based IoT testbed with real network traffic. Evaluate performance under production load and network variability.

\textbf{Multi-Model Comparison}: Benchmark additional LLMs (GPT-4, Claude, local Llama models) for accuracy/latency tradeoffs.

\textbf{Automated Red Teaming}: Implement LLM-based adversarial fuzzing to continuously discover attack vectors.

\section{Future Work}

While our hybrid architecture demonstrates the effectiveness of zero-shot general-purpose LLMs for IoT access control, several promising avenues warrant further investigation.

\subsection{Domain-Specific LLM Fine-Tuning}

The current system leverages pre-trained general-purpose models (Llama 3.3 70B), which demonstrates broad generalizability but incurs API costs and latency. Fine-tuning smaller domain-specific models (e.g., Llama 3 8B) on IoT-specific threat patterns could yield several benefits:

\textbf{Latency Reduction}: Smaller fine-tuned models deployed on-premise could achieve sub-50ms inference times compared to the current 150ms cloud API calls, enabling real-time edge deployment scenarios.

\textbf{Cost Elimination}: Local inference eliminates per-request API costs (\textasciitilde\$0.01/request), making the solution economically viable for large-scale IoT deployments with millions of daily access decisions.

\textbf{Enhanced Privacy}: On-premise models eliminate external API dependencies, addressing privacy concerns in sensitive environments such as healthcare IoT or critical infrastructure.

\textbf{Specialized Accuracy}: Training on curated datasets of IoT-specific attacks (device impersonation, semantic policy evasion, time-based bypasses) could improve detection rates beyond the current 82.1\% accuracy.

Key research questions include: (1) Can a 7B parameter fine-tuned model match GPT-4-class accuracy while reducing inference time by 3×? (2) What is the optimal training data composition (legitimate vs. attack scenarios) for IoT threat detection? (3) How does model size affect the accuracy-latency tradeoff in production access control systems?

Dataset requirements would include 10,000+ labeled IoT access scenarios spanning diverse device types, policy violations, and representative attack vectors, requiring collaboration with industry partners managing large-scale IoT deployments.

\section{Conclusion}

We presented IoT-Access-Sentinel, a hybrid framework combining deterministic user authorization with multi-agent LLM reasoning for IoT access control, addressing the MITRE M0801 gap. Our evaluation on 103 test scenarios demonstrates a statistically significant 16.5 percentage point accuracy improvement over a fair RBAC baseline with authentication (94.2\% vs 77.7\%, McNemar's $\chi^2$ = 9.0, p $<$ 0.01). The deterministic pre-check layer achieves 41\% cost savings while ensuring zero-doubt security for user authentication. The hybrid approach demonstrates particular strength in handling semantic attacks and context-aware decisions where pure rule-based systems struggle. This work provides quantitative evidence that hybrid LLM architectures can effectively bridge the semantic gap in IoT security with both accuracy and efficiency.
